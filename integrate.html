SAP's first working primitive compares declared AI execution alternatives against constraints that matter: task quality, local-only privacy, optional human review, disclosed cost, and energy evidence. The integration is voluntary and local-first.

Scope: This is a prototype decision helper, not a ratified protocol, energy meter, model router, or automatic enforcement layer. You must provide options and evidence, connect the result to your own execution code, and independently verify real outcomes.

1. Use the zero-dependency core

For JavaScript applications, download sap-core.js or copy it from GitHub. No API key, account, build step, or network permission is required.

const SAP = require("./sap-core");

const options = [
  {
    id: "local",
    location: "local",
    quality: 0.85,        // application-supplied proxy
    costUSD: 0.01,
    latencyMs: 1300,
    energyKwh: null,     // do not invent measurements
    energyEvidence: "unknown"
  },
  {
    id: "cloud",
    location: "remote",
    quality: 0.92,
    costUSD: 0.005,
    latencyMs: 600,
    energyKwh: null,
    energyEvidence: "unknown"
  }
];

const plan = SAP.evaluate(options, {
  mode: "balanced",
  minimumQuality: 0.8,
  localOnly: true
});

console.log(plan.selected?.id); // "local"
console.log(plan.reason);
// No remote call has been made.

The same file can be loaded in a browser with a normal script tag, where it exposes window.SAPCore.

2. Distinguish truth from assumptions

// A receipt can describe a plan, not prove success.
const receipt = SAP.makeReceipt(plan.selected, {
  status: "planned",
  demo: false
});

// Never mark an outcome "verified" without
// an external verification reference.
  • Energy measurements must carry their evidence class: measured, estimated, provider_reported, or unknown.
  • Missing values stay unknown. Local does not automatically mean lower-carbon or lower-cost.
  • Local-only and required human review are explicit selection constraints; real enforcement remains the application's responsibility.
  • The current core does not track prompts, maintain profiles, or communicate with a central SAP server.

What's next?

Our proposed direction is an evidence-carrying impact envelope, interoperable with existing environmental, observability, model-routing, and human-authorization systems. Those integrations are future work—not shipped features.
